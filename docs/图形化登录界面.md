# 图形化登录界面

这个分支把 FlexLoginUI 那套登录页直接接进了 LibreLogin，不用再额外装 AuthMe 或 FlexLoginUI。

## 客户端会看到啥

- `1.21.6` 及以上客户端：Minecraft 原生对话框，登录、注册、二次验证码都能直接填。
- 更老的客户端：自动换成铁砧输入页。注册确认和二次验证码会分两步问，不然一个铁砧框也塞不下。
- 要是两种界面都关了：LibreLogin 原来的聊天命令照常跑，不会把登录彻底整没。

Velocity 端会在玩家进入配置里的验证服后，由代理直接把界面发给客户端。验证服可以继续使用 NanoLimbo，不需要也不能往 NanoLimbo 里塞 Bukkit 插件。Floodgate 玩家沿用 LibreLogin 原本的免登录处理，不会莫名其妙再弹一层表单。

## 先把依赖装对

这个版本需要外置的 `PacketEvents 2.13.0`：

- Velocity 用 `packetevents-velocity-2.13.0.jar`。
- Paper 用 `packetevents-spigot-2.13.0.jar`。
- 不要把旧版和新版一起放进 `plugins`，两个版本同时接管数据包会直接冲突。

插件现在会把 PacketEvents 当成必需依赖。没装或版本太旧时就直接停下来报明白，省得 LibreLogin 看着绿油油，登录页却装死。

## 配置在哪

首次启动后，主配置里会多出 `authentication-ui`。常用的几项：

```hocon
authentication-ui {
  enabled=true
  allow-close=false
  open-delay-ticks=5

  dialog {
    enabled=true
    horizontal-buttons=true
  }

  anvil {
    enabled=true
  }
}
```

标题、按钮、报错和输入框文字也都在同一段里，直接改就行。`allow-close=false` 时，玩家点退出或硬关界面会被踢出服务器；改成 `true` 后只会关页，聊天命令还能继续用。

## 认证逻辑没另起炉灶

界面只负责收输入，密码哈希、失败次数、注册限制、二次验证、认证事件和登录后传送，全部继续调用 LibreLogin 原来的处理链。以后修认证逻辑，不用再同时维护一套偷偷复制出来的密码判断。
